## Resolved every non-auth Sprint 1 BE gap and shipped the Dashboard module

### BE: Closed gaps #4–#14, #23–#36, #40 in a single cleanup pass

Yesterday's daily covered the first wave (4 gaps + the FE auth screens). Today's pass closed the **rest of the verification doc** — all the items uncovered by the deeper Figma analysis, plus the original code-only gaps that hadn't been touched.

Schema changes in `apps/sfi-api/prisma/schema.prisma`:

- **`Deal.currency: Currency @default(USD)`** — closes gap #11 / #28. The Deals List in Figma shows a Currency column on every row, but the create form has no currency selector. The decision (per the verification doc) was to default to `USD` at the schema level, with the option to override in `CreateDealDto`. Existing rows will get `USD` on migration.
- **`Deal.suspendedReason: String?`** — closes gap #34. The Deal Overview Suspended state shows a yellow banner with text like "Client is currently unresponsive." That's a stored value, not a hardcoded UI string. Field is nullable; service auto-clears it when the status moves out of `SUSPENDED`.
- **`@@index([status])` on Deal** — supports the new `?status=` filter and the `groupBy({ by: ['status'] })` used by the counts endpoint.
- **`SettlementRunStatus.CANCELLED`** — closes gap #33. The Figma Latest Settlement card shows a "Cancelled" badge. Existing enum had `DRAFT / PREVIEWED / FINALIZED / VOIDED` — added `CANCELLED` as a fifth value semantically distinct from `VOIDED` (cancelled = abandoned mid-flow, voided = invalidated after finalize).

Key changes in the Deals module:

- **`PATCH /deals/:id`** — closes gap #4. New `update()` method on `DealsService`. Reuses `findOne()` for the 404 check, performs the partial update via `prisma.deal.update`, then emits an audit log entry. The audit action is dynamic: `STATUS_CHANGED` if the status changed, otherwise `UPDATED`. Metadata always includes the changed fields list. When status moves out of `SUSPENDED` and the caller didn't explicitly set `suspendedReason`, the service auto-nullifies it. Service-level cross-field date validation as defense in depth (DTO already has `@IsAfterDate`).
- **`GET /deals/counts`** — closes gap #7. Returns `{ all, draft, active, suspended, closed }` via a single `prisma.deal.groupBy({ by: ['status'], _count: { _all: true } })` call. The FE picks the 4 buckets it shows in the design (the design omits the Suspended tab). Single round-trip, much faster than 5 separate counts.
- **`?status=` and `?search=` on `GET /deals`** — closes gaps #5 and #6. Created a new `DealListQueryDto extends PaginationQueryDto` so the generic pagination DTO stays clean (it's used by 8 other modules). The search does a case-insensitive `contains` on both `name` and `description` via Prisma `where: { OR: [...] }`.
- **`_count` block on `DealResponseDto`** — closes gap #10. `findOne()` includes counts for participants, ruleSnapshots, revenueBatches, settlementRuns. The list endpoint includes only `participantsCount` (the only count needed in list views). All counts are optional fields on the DTO so the mapper passes them through when present, omits them when absent.
- **`totalRevenue` aggregate on `findOne()`** — closes gaps #13 / #36. The Deal Overview "Total Revenue" stat ($200M in the design) is the sum of `RevenueBatch.totalAmount`. Computed as a separate `prisma.revenueBatch.aggregate({ _sum })` call (kept separate from the main `findOne` `include` to avoid pulling full revenue batch rows into memory).
- **Custom `@IsAfterDate` validator** — closes gap #12. New file at `apps/sfi-api/src/common/validators/is-after-date.validator.ts`. Cross-field validator that compares two ISO date strings on the same DTO. Used on `terminationDate` in both `CreateDealDto` and `UpdateDealDto`. Service-level validation also added to `update()` because the DTO can only see the request body — when the user updates only `terminationDate`, the validator can't compare against the persisted `effectiveDate`, so the service does the comparison itself.

Key changes in the Settlement module:

- **`SettlementRunResponseDto` enrichments** — closes gap #32. Added optional fields: `proofHash`, `ruleSnapshotVersion`, `revenueBatchCount`, `totalRevenue`, `finalizedAt` (alias of `executedAt` — same value, clearer name for the FE). The FE Latest Settlement card on Deal Overview now gets every field it needs from `GET /deals/:id/settlement-runs?limit=1&sortBy=createdAt&sortOrder=desc` in a single call instead of needing an N+1 fetch to the proof endpoint.
- **`listRuns()` Prisma include** — joins `ruleSnapshot.version`, `_count.settlementRevenueLinks`, the latest `proofRecords` (take 1), and the linked revenue batch totals so the enrichments can be populated without separate queries.
- **`getRun()` updated similarly** — same enrichments now flow through the detail endpoint too.
- **`mapRunToResponse()` signature change** — accepts an optional `enrichments` parameter; spreads the new fields conditionally so unenriched callers (e.g. `createRun`, `correctionRun` which don't have proof yet) keep working.

### BE: New Dashboard module from scratch

This is a brand new feature module — `apps/sfi-api/src/modules/dashboard/`. Closes gaps #8, #9, #23, #24, #25.

- **`DashboardController`** at `controllers/dashboard.controller.ts` — two routes: `GET /dashboard/summary` and `GET /dashboard/pending-reviews`.
- **`DashboardService`** at `services/dashboard.service.ts`:
  - `getSummary()` — runs all 5 stats in parallel via `Promise.all` (deal count, active deal count, pending revenue batch count, previewed settlement run count, FINALIZED settlement run sum). Single round-trip across the wire. Always returns 0 values when no data.
  - `getPendingReviews()` — fetches up to 10 PENDING revenue batches and 10 PREVIEWED settlement runs in parallel, joining each with `deal.name` via Prisma `include`. For settlement runs, computes a "Run #N" label by counting how many runs the deal has up to and including the current one. Capped at 10 each, so the extra count queries are bounded.
- **DTOs** at `dto/index.ts` — `DashboardSummaryResponseDto`, `DashboardPendingReviewsResponseDto`, `PendingRevenueBatchDto`, `PendingSettlementRunDto`. All Swagger-annotated.
- **`DashboardModule`** registered in `app.module.ts`.
