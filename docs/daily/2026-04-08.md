## Closed Sprint 1 BE gaps and initiated FEA Admin Portal frontend

### BE: Patched all 14 Sprint 1 gaps before FE kickoff

Ran full BE verification against the Sprint 1 tickets (FEA-1 through FEA-8) and found 14 gaps. Closed all of them before FE work started so no screen goes live against a missing endpoint.

Key changes in `apps/sfi-api`:

- **`PATCH /deals/:id`** — `UpdateDealDto` was already defined in `dto/index.ts` but had no controller route or service method. Added `update()` to `DealsService` (reuses `findOne()` for the 404 check, then `prisma.deal.update`, then audit log `UPDATED`). Added `@Patch(':id')` to `DealsController`. This unblocks FEA-8 (Edit Deal).
- **Status + search filters on `GET /deals`** — Extended `PaginationQueryDto` with `status?: DealStatusDto` and `search?: string`; updated `findAll()` to build a `where` clause from them. `search` does a case-insensitive `contains` on both `name` and `description`. This unblocks FEA-5 (Deals List filtering).
- **`participantsCount` on deal responses** — Added `_count: { select: { participants: true } }` to the `findOne` Prisma query and exposed `participantsCount: number` on `DealResponseDto` and `DealMapper.toResponse()`. This unblocks FEA-7 (Deal Overview stats card).
- **Cross-field date validation** — Added a `@ValidateIf` + custom `@IsAfterDate('effectiveDate')` decorator on `terminationDate` in both `CreateDealDto` and `UpdateDealDto`. Throws 400 if termination is not after effective date.

Auth endpoints (FEA-1, FEA-2, FEA-3 — Login, Register, Forgot Password) remain missing from the BE because no `User` model or `AuthModule` exists in the schema yet. FE auth screens are scaffolded with placeholder logic for now; will be wired once the auth BE milestone is scheduled.

### FE: Scaffolded `apps/sfi-admin` and built auth screens

Initialized the admin portal as a new Next.js 15 app inside the monorepo at `apps/sfi-admin`. Package name `@sfi-fea/sfi-admin`, port 3002.

**Project scaffold:**
- `tsconfig.json` with strict settings as per `FRONTEND_ADMIN_STANDARDS.md §2`: `strict`, `noUncheckedIndexedAccess`, `noUnusedLocals`, `noImplicitReturns`, `exactOptionalPropertyTypes`, path alias `@/*` → `src/*`
- `src/lib/env.ts` — Zod-validated env schema; throws at startup if `NEXT_PUBLIC_API_URL` is missing
- `src/lib/axios.ts` — configured Axios instance with request interceptor (Bearer token from `localStorage`) and 401 response interceptor (clears token, redirects to `/login`)
- `src/lib/query-client.ts` — `QueryClient` singleton with 5-minute `staleTime` and no retry on 4xx
- `src/constants/` — seeded `routes.ts`, `api.ts`, `query-keys.ts`, `ui.ts` with all known endpoints and deal status badge variants
- `src/types/` — `deal.types.ts`, `api.types.ts` with `PaginatedResponse<T>` and `ApiError`

**Auth screens (FEA-1, FEA-2, FEA-3):**

All three screens live under `app/(auth)/`. They use shadcn `Card`, `Input`, `Button`, `Label`, and `Form` (react-hook-form + zod). No API calls yet — submit handlers log to console until the auth BE is built.

- **Login** (`app/(auth)/login/page.tsx`) — email + password fields, "Remember me" checkbox, "Forgot password?" link to `/forgot-password`, submit button. Form validation: email must be valid, password min 8 chars.
- **Register** (`app/(auth)/register/page.tsx`) — first name, last name, email, password, confirm password. Validation: confirm password must match, zod `superRefine`. Note: this screen may be admin-only (invite flow) once the auth BE is defined — marked with a `TODO` comment.
- **Forgot Password** (`app/(auth)/forgot-password/page.tsx`) — email field only. On submit shows a success state ("Check your email") without an API call. Will wire to `POST /auth/forgot-password` once that endpoint exists.

Auth layout (`app/(auth)/layout.tsx`) centers the card on a neutral background, no sidebar. Dashboard layout (`app/(dashboard)/layout.tsx`) scaffolded with sidebar shell and header — content is a placeholder pending Sprint 2.
