## FEA-6 — Create Deal

**`src/components/deals/CreateDealDrawer.tsx`**

Controlled by a `isOpen` boolean prop. Full-width drawer from the right using shadcn `Sheet`.

Form: react-hook-form + Zod. Fields:

| Field | Validation |
|---|---|
| Deal Name | required, 1–255 chars |
| Description | optional, max 2000 chars with live counter |
| Status | select (DRAFT default, ACTIVE, SUSPENDED, CLOSED) |
| Effective Date | required, date picker |
| Termination Date | optional, cross-field `refine` — must be after effective date if provided |

On submit: `POST /deals` via `useCreateDeal()` mutation hook. On success: invalidates `queryKeys.deals.all` + `queryKeys.deals.counts`, closes drawer, shows toast "Deal created". On error: inline form error under the submit button.

The `terminationDate > effectiveDate` rule enforced both in Zod schema (FE) and in the service layer (BE) — double validation as defence in depth.

All fields confirmed present in `SettlementRunResponseDto` after April 9's BE enrichment.

**Quick Action buttons:** New Revenue Batch, New Settlement Run, New Participant, New Rule Snapshot — present in the layout, disabled with a "Coming in next sprint" tooltip. No route for them yet.
