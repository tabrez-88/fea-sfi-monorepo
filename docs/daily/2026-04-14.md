## BE — Auth-Scoped Data Access (userId on Deal)

The auth subsystem from April 13 issued JWTs, but all data endpoints still returned global results — any authenticated user could see every deal. Fixed today.

### Root cause

`Deal` model had no `userId` field — no way to filter by owner.

### Schema change

```prisma
model Deal {
  userId   String  @map("user_id")
  user     User    @relation(fields: [userId], references: [id])
  @@index([userId])
}

model User {
  deals  Deal[]
}
```

### Database operations

```bash
# 1. Wiped existing test deals (staging DB — no real data yet)
echo "TRUNCATE deals CASCADE;" > /tmp/t.sql
npx prisma db execute --schema prisma/schema.prisma --file /tmp/t.sql

# 2. Pushed schema (added user_id column + FK + index)
npx prisma db push
```

### Services updated

Every service method that reads or writes deals now takes `userId` as its first argument and enforces ownership:

| Service | Pattern |
|---|---|
| `DealsService` | All methods: `findAll(userId, query)`, `findOne(userId, id)`, `create(userId, dto)`, `update(userId, id, dto)`, `getCounts(userId)`. Added `assertDealOwner(dealId, userId)` public helper. |
| `DashboardService` | `getSummary(userId)` and `getPendingReviews(userId)` — all Prisma queries now filter through `deal: { userId }` |
| `ParticipantsService` | `create(userId, dealId, dto)` + `findAllByDeal(userId, dealId, query)` — uses `dealsService.assertDealOwner()` |
| `RevenueService` | All methods take `userId`. Private `assertDealOwner` + `assertBatchOwner` helpers. |
| `RulesService` | All methods take `userId`. Private `assertDealOwner` + `assertSnapshotOwner` helpers. |
| `SettlementService` | All methods take `userId`. Private `assertDealOwner` + `assertRunOwner` helpers. |

**Ownership check pattern for resource-only endpoints** (e.g. `GET /revenue-batches/:id` — no `dealId` in path):
```typescript
const batch = await this.prisma.revenueBatch.findUnique({
  where: { id },
  select: { id: true, deal: { select: { userId: true } } },
});
if (!batch || batch.deal.userId !== userId) {
  throw new NotFoundException(`Revenue batch with ID ${id} not found`);
}
```
Returns identical `NotFoundException` for "not found" and "belongs to another user" — no ownership leak.

## FE ↔ BE Connection Fixes

Two bugs prevented the admin portal from reaching the API at all:

### 1. Wrong API base URL

`NEXT_PUBLIC_API_URL=http://localhost:3001` — missing the `/api/v1` global prefix. Every request was hitting `/auth/register` instead of `/api/v1/auth/register` and getting a 404 that surfaced as a CORS error.

**Fix:** `apps/sfi-admin/.env.local`
```
NEXT_PUBLIC_API_URL=http://localhost:3001/api/v1
```

### 2. CORS origin missing port 3002

`CORS_ORIGIN=http://localhost:3000` — the admin portal runs on port 3002, so every preflight was rejected.

**Fix:** `apps/sfi-api/.env`
```
CORS_ORIGIN=http://localhost:3000,http://localhost:3002
```

## Database Provisioning (auth tables + runNumber)

First-time run of the sfi-admin against the staging database revealed the auth tables (`users`, `refresh_tokens`, `password_reset_tokens`) had never been pushed. The `run_number` column also blocked the push because the `settlement_runs` table had 3 existing rows.

**Resolution sequence:**
1. Temporarily added `@default(0)` to `SettlementRun.runNumber` in schema
2. Ran `npx prisma db push` — pushed successfully (3 existing rows got `run_number = 0`)
3. Removed `@default(0)` from schema
4. Ran `npx prisma db push` again — dropped the DB-level default, leaving column NOT NULL without default (matching intended design where app code always sets it)

All auth tables are now live in the staging database. Register and login endpoints functional.
